# Wig Security Deposit — staged implementation
This is an additive release candidate, not a production deployment. Current production worker is not stored in this repository. The patch script targets the router and classic admin navigation observed in the live worker; re-check exact anchors on a fresh private export. Keep the live worker source and secrets private.

## Scope and launch gates
- Approved mcwig_cases_v1 cases are listed automatically, with priority from existing wig_requests and maker status from maker_jobs. No donor record duplication.
- Versioned acceptance and an effective timestamp prevent retrospective charges. Existing approval email stays untouched until the relay is updated. Historical records remain read-only unless an individually approved, separately designed policy is adopted.
- ₹0 manufacturing/purchase cost; ₹2,000 separately disclosed actual processing/packaging/courier charges; ₹8,000 refundable liability. No automatic confiscation or ownership transfer. Normal wear never charged. Reasonable documented deductions, hardship waiver and medical extension.
- New SQL tables store a revisioned audit trail and HOLD email intents. No direct email calls, no bank transfer calls, no collection without explicit live gate.
- Confirm 100% human hair against maker specification before delivery. Return period starts on actual verified delivery. A timely return request protects beneficiary from transit delay.
- Keep current release flow and inventory unchanged until tested integration: once policy is legally approved, implement server-side release/handover check for newly enrolled cases, use existing inventory IDs and professional sanitisation/reuse inspection. Do not claim stock reconciliation until tested. Approval remains independent of payment.
- Email relay: wire held kinds to the existing verified Apps Script relay using idempotency keys, immutable event snapshots (not mutable current row), and explicit send/delivery audit; update approval template only after terms have been legally reviewed. A reminder scheduler must use unique case/deadline/offset keys. These relay, stock and reminder integrations are pending, not active.
- Migration only in isolated staging D1, no patient PII in test fixtures. Apply SQL, add module, run patch script on a fresh private staging copy of worker.js, then test admin and staff access, same-origin checks, legacy records, approval, duplicate UTR, concurrent revisions, maker received check, delivery date, expiry, medical extension, return, deductions, refund and all existing workflows.
- Set MC_WIG_DEPOSIT_ENABLED=true for staging UI only. MC_WIG_DEPOSIT_LIVE defaults off. MC_WIG_DEPOSIT_EFFECTIVE_AT must be a ten-digit Unix timestamp reflecting prospective approved policy start. Financial activation requires approved trustees' resolution and lawyer/CA review, successful isolated E2E including verified email relay and stock integration, and production rollback plan.
- No promise of error-free deployment. Do not activate or merge/deploy until remaining integration and regression tests pass.
